# Краткий отчёт по финальному прогону Evaluation Runner v0.3

## Общая информация

Проверка выполнена на контрольном наборе из 50 вопросов с помощью workflow `NPD Evaluation Runner v0.3`.

В прогоне использовалась актуальная двухуровневая RAG-архитектура:

- `RAW_CONTEXT` — единственная доказательная база;
- `MINI_WIKI_CONTEXT` — вспомогательный слой, который не может использоваться как источник;
- программная проверка пары `[doc_id / chunk_id]`;
- отдельная LLM-оценка ответа;
- safety guard для рискованных запросов;
- строгий fallback при отсутствии прямого подтверждения в RAW-контексте.

## Итоговые результаты

| Показатель | Результат |
|---|---:|
| Всего вопросов | 50 |
| Успешные ответы | 47 |
| Общая успешность | 94% |
| Корректные fallback и safety-отказы | 100% |
| Содержательные ответы с проверяемыми RAW-источниками | 100% |
| Типичное время ответа в Telegram | 6–9 секунд |

## Что проверялось

В контрольный набор входили:

- типовые вопросы по НПД;
- вопросы о регистрации, ставках, чеках, сроках и ограничениях;
- формулировки с уточняющими условиями;
- вопросы, для которых в базе нет достаточного подтверждения;
- запросы, связанные с уклонением от налогов и нарушением правил.

Для обычного ответа модель должна была:

1. ответить именно на заданный аспект вопроса;
2. использовать только факты из `RAW_CONTEXT`;
3. указать валидную пару `[doc_id / chunk_id]`;
4. не цитировать Mini-Wiki и служебные документы.

Если прямого подтверждения в RAW-базе не было, ожидаемым результатом считался строгий fallback без источников.

## Основные выводы

Финальный прогон подтвердил, что система в большинстве случаев корректно находит нужные RAW-чанки, формирует краткий ответ и указывает проверяемый источник.

Программная проверка источников исключает ссылки на несуществующие чанки и запрещённые Mini-Wiki-документы. Если валидный источник отсутствует, ответ автоматически заменяется fallback.

Все внебазовые и рискованные запросы в контрольном наборе были обработаны корректно. Это подтверждает работоспособность safety guard и строгой fallback-логики.

Три ответа не прошли итоговую оценку. Они показали, что качество системы по-прежнему зависит от полноты базы знаний, качества retrieval и точности соответствия ответа конкретному аспекту вопроса.

## Ограничения оценки

- Набор из 50 вопросов достаточен для проверки MVP, но не заменяет более широкий production-тест.
- LLM-as-a-judge используется как вспомогательный способ оценки и не исключает ручную проверку.
- Программный verifier проверяет наличие и допустимость источника, но смысловое соответствие факта источнику оценивается отдельно.
- Результаты относятся к текущей версии базы знаний, промпта и retrieval-логики.

## Итог

Целевые требования MVP выполнены: ассистент отвечает на основе проверенной базы знаний, показывает RAW-источники, не использует Mini-Wiki как доказательство и безопасно обрабатывает неподтверждённые и рискованные запросы.

Общая успешность финального прогона составила **94%**.
