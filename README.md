# Проверяемый RAG-ассистент для самозанятых

MVP Telegram-ассистента по вопросам налога на профессиональный доход (НПД), который отвечает только на основе проверенной базы знаний, указывает источники и безопасно обрабатывает неподтверждённые и рискованные запросы.

## Цель проекта

Создать справочного ассистента для начинающих самозанятых, который:

- отвечает на типовые вопросы по НПД;
- использует только проверенную базу знаний;
- не опирается на внешние знания модели;
- показывает проверяемые источники;
- использует строгий fallback, если прямого подтверждения в базе нет;
- блокирует запросы, связанные с нарушением правил и уклонением от налогов.

## Статус

Проект завершён на уровне MVP.

Реализовано:

- Telegram-интерфейс;
- двухуровневая RAG-архитектура;
- отдельный RAW- и Mini-Wiki retrieval;
- программная проверка источников;
- safety guard;
- строгий fallback;
- пакетная оценка качества на 50 вопросах;
- логирование результатов в Google Sheets.

## Технический стек

- Интерфейс: Telegram-бот
- Оркестрация: self-hosted n8n
- LLM: OpenAI GPT-4.1 mini
- Embeddings: OpenAI `text-embedding-3-small`
- Vector DB: Qdrant
- База знаний: Markdown-файлы
- Реестр документов: `documents_registry.csv`
- Оценка качества: LLM-as-a-judge + ручная проверка
- Хранение результатов тестов: Google Sheets


## Два слоя базы знаний

### RAW_CONTEXT

Единственная доказательная база.

Используется для:

- фактических утверждений;
- финального ответа;
- указания источников.

### MINI_WIKI_CONTEXT

Вспомогательный слой для понимания темы и различения сценариев.

Mini-Wiki:

- не является доказательной базой;
- не может использоваться как источник;
- не цитируется в ответах;
- не заменяет RAW-документы.

## Состав базы знаний

Актуальное состояние коллекции `npd_knowledge_v1`:

```text
36 документов
258 чанков
184 RAW-чанка
74 Mini-Wiki-чанка
```

Состав:

- 25 RAW-документов;
- 8 тематических Mini-Wiki-документов;
- 3 служебных документа: `glossary`, `fallback_rules`, `negative_scenarios`.

## Verified RAG правила

Система следует следующим правилам:

- фактические ответы формируются только по `RAW_CONTEXT`;
- Mini-Wiki не используется как доказательство;
- внешние знания и неподтверждённые выводы запрещены;
- каждый фактический ответ должен содержать проверяемый RAW-источник;
- для fallback и safety-отказов источники запрещены;
- каждая пара `[doc_id / chunk_id]` проверяется программно;
- если источник отсутствует в текущем RAW-контексте, ответ заменяется fallback.

Строгий fallback:

```text
В базе знаний нет достаточной информации для ответа на этот вопрос
```

## Safety guard

Блокируются запросы, связанные с:

- скрытием доходов;
- уклонением от налогов;
- занижением дохода;
- фиктивными и поддельными чеками;
- обходом ограничений НПД.

Такие запросы не передаются в генерационный RAG-контур.

## Оценка качества

Контрольный прогон выполнен на 50 вопросах.

Результаты:

```text
94% успешных ответов
100% корректных fallback для внебазовых и рискованных запросов
100% содержательных ответов с проверяемыми источниками
```

Обычное время ответа в Telegram составляло примерно 6–9 секунд.

Важно: программная проверка подтверждает наличие и допустимость источника, а смысловое соответствие ответа вопросу дополнительно оценивается LLM-судьёй и вручную.

## Правило ingestion

В embeddings и Qdrant попадают только документы, для которых выполнены условия:

```text
status = active
retrieval_eligible = true
```

Документы со статусами `reference_only`, `pending_review`, `excluded` и `outdated` не должны использоваться как доказательная база.

## Запуск

Для воспроизведения проекта необходимы:

- self-hosted n8n;
- Qdrant;
- OpenAI API key;
- Telegram Bot API token;
- Google Sheets OAuth2 для Evaluation Runner.

После импорта workflow необходимо заново настроить credentials и проверить параметры Qdrant, Telegram и Google Sheets.

## Ограничения MVP

Текущая версия:

- не является юридической или налоговой консультацией;
- охватывает ограниченный набор сценариев НПД;
- требует регулярного обновления базы знаний;
- не рассчитана на высокую параллельную нагрузку;
- требует дополнительной проверки спроса и экономики перед коммерческим запуском.

## Итог

MVP подтвердил техническую реализуемость проверяемого RAG-ассистента по НПД: система работает в Telegram, отвечает по базе знаний, показывает источники и безопасно обрабатывает неподтверждённые и рискованные запросы.

При этом коммерческая модель пока не доказана и требует отдельной проверки спроса, стоимости сопровождения и привлечения пользователей.
